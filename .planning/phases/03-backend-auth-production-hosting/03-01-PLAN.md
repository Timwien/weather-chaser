Create `apps/web/api/proxy/weather.ts` — Vercel Web Fetch handler that forwards to Open-Meteo:
- Accept GET with query params: `latitude`, `longitude`, `forecast_days` (default 16)
- Also forward `hourly` param — client may specify exactly which fields it wants; if not present, default to `temperature_2m,precipitation,sunshine_duration,wind_speed_10m`
- Forward `timezone` param (default `Europe/Berlin`)
- If `process.env.OPEN_METEO_API_KEY` is set, append `apikey` to upstream URL
- Return upstream response body with headers:
  ```
  Content-Type: application/json
  Cache-Control: public, s-maxage=21600, stale-while-revalidate=3600
  Access-Control-Allow-Origin: *
  ```
- Return 400 if `latitude` or `longitude` missing
- Export default as `{ async fetch(request: Request): Promise<Response> }` object (Vercel Web handler format — NOT `export default function handler(req, res)`)

Create `apps/web/api/proxy/overpass.ts` — Vercel Web Fetch handler that forwards Overpass QL queries:
- Accept POST with raw Overpass QL body (the client sends `data=<encoded query>` as form-urlencoded, same as existing overpass.ts service)
- Forward to `https://overpass-api.de/api/interpreter` with same method + body
- Set `User-Agent: WeatherChaser/1.0 (weatherchaser.vercel.app)` on upstream request (Overpass usage policy)
- Return upstream response with headers:
  ```
  Content-Type: application/json
  Cache-Control: public, s-maxage=86400, stale-while-revalidate=3600
  Access-Control-Allow-Origin: *
  ```
- Return 405 for non-POST requests
- Export default as Web handler object

Both functions use `process.env` for server-side config — no `VITE_` prefix.

Create `apps/web/api/proxy/nominatim.ts` — Vercel Web Fetch handler:
- Accept GET with query params: `q` (search query), `limit` (default 5)
- Also forward `format=json`, `addressdetails=0` to upstream
- Forward to `https://nominatim.openstreetmap.org/search`
- Set on upstream request:
  - `User-Agent: WeatherChaser/1.0 (weatherchaser.vercel.app)` — Nominatim policy requires valid User-Agent
  - `Referer: https://weatherchaser.vercel.app`
- Return upstream response with headers:
  ```
  Content-Type: application/json
  Cache-Control: public, s-maxage=3600, stale-while-revalidate=600
  Access-Control-Allow-Origin: *
  ```
- Return 400 if `q` param missing
- Export default as Web handler object

Create `apps/web/api/keepalive.ts` — Vercel cron endpoint to prevent Supabase free tier auto-pause:
- Import `createClient` from `@supabase/supabase-js` — NOTE: this means `@supabase/supabase-js` must be added to apps/web dependencies. Run `pnpm add @supabase/supabase-js` in apps/web before writing the file.
- Create a Supabase client using `process.env.SUPABASE_URL` and `process.env.SUPABASE_ANON_KEY` (server-side env vars, NO `VITE_` prefix)
- Run `await supabase.from('saved_routes').select('count').limit(0)` (lightweight ping; table may not exist yet — error is acceptable, the HTTP request itself keeps Supabase alive)
- Return `{ status: 'ok' }` with 200 regardless of DB result
- Export default as Web handler object

Create `apps/web/vercel.json`:
```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "framework": "vite",
  "fluid": true,
  "regions": ["fra1"],
  "rewrites": [
    { "source": "/api/(.*)", "destination": "/api/$1" },
    { "source": "/((?!api/).*)", "destination": "/index.html" }
  ],
  "functions": {
    "api/**/*.ts": {
      "maxDuration": 60
    }
  },
  "crons": [
    { "path": "/api/keepalive", "schedule": "0 12 */3 * *" }
  ]
}
```

Critical: the SPA rewrite `/((?!api/).*)` uses a negative lookahead to pass `/api/*` to serverless functions and route everything else to `index.html`. A simple `(.*)` → `index.html` would intercept API calls.
