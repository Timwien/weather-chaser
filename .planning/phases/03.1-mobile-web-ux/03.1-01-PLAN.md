Create `apps/web/src/hooks/useIsMobile.ts`. SSR-safe `matchMedia('(max-width: 768px)')` boolean hook — same pattern `themeStore.ts` already uses for `prefers-color-scheme`. 768px is the locked breakpoint (matches every existing `@media (max-width: 768px)` rule in the CSS).

```typescript
import { useEffect, useState } from 'react';

const QUERY = '(max-width: 768px)';

function read(): boolean {
  return typeof window !== 'undefined' && window.matchMedia(QUERY).matches;
}

/** True on phone/portrait-tablet viewports (≤768px). Updates live on resize/orientation change. */
export function useIsMobile(): boolean {
  const [isMobile, setIsMobile] = useState<boolean>(read);

  useEffect(() => {
    const mq = window.matchMedia(QUERY);
    const onChange = () => setIsMobile(mq.matches);
    mq.addEventListener('change', onChange);
    // sync once in case the media state changed between SSR/first render and effect
    setIsMobile(mq.matches);
    return () => mq.removeEventListener('change', onChange);
  }, []);

  return isMobile;
}
```

No new dependency. No hardcoded strings (none are user-facing here).

**Single source of truth — `getSheetHeights()` (REQUIRED, checker WARNING 4):**
Export ONE helper that returns the canonical detent heights in pixels (how much of the screen the sheet covers at each detent), and use it INTERNALLY to derive the sheet's own translateY for each snap. Plan 03 imports this exact function for map padding — there must be no second copy of these numbers anywhere.
```typescript
/**
 * Canonical detent heights in px (how much of the viewport the sheet covers at each snap).
 * SINGLE SOURCE OF TRUTH: the sheet uses this for its own translateY, and Plan 03
 * imports it to pad the map by the sheet's real coverage. Do NOT duplicate these numbers.
 * Read `window.innerHeight` at call time (Vite SPA, no SSR for this route).
 */
export function getSheetHeights(): [number, number, number] {
  const vh = typeof window !== 'undefined' ? window.innerHeight : 800;
  const PEEK = 84;                       // handle + summary strip only
  return [PEEK, Math.round(vh * 0.5), vh]; // [peekPx, halfPx, fullPx]
}
```
Inside the component, derive the per-snap translateY from these heights: the sheet body is full-height (`height: 100dvh`) and is translated DOWN by `fullPx - heights[snapIndex]` so only `heights[snapIndex]` px remain visible (translateY 0 at full, large translateY at peek). Recompute on resize.

**Snap mechanics (follow RESEARCH Pattern 2 + anti-patterns exactly):**
- Use `getSheetHeights()` for the three detent heights; convert to translateY as above. Store the current translateY in a ref during drag.
- Outer fixed wrapper: `position: fixed; left:0; right:0; bottom:0; height: 100dvh` with the CSS transform applied. Apply `transition: transform 200ms ease-out` ONLY when not actively dragging (toggle a `dragging` ref / data-attribute that removes the transition class during drag).
- Drag listener is bound ONLY to the handle `<div>` (NOT the whole sheet). Handle has `touch-action: none`. On `pointerdown`: `handleEl.setPointerCapture(e.pointerId)`, record start Y + current translateY, set `dragging`. On `pointermove`: write `sheetEl.style.transform = translateY(clamped)` directly via ref — NO React state update (prevents re-render thrash → 60fps). On `pointerup`/`pointercancel`: compute nearest snap from the released translateY (compare against the translateY of each detent derived from `getSheetHeights()`), clear `dragging`, call `onSnapChange(nearestIndex)`, release pointer capture. The committed `snapIndex` prop drives the transform via `useEffect`/style so the controlled value and the visual stay in sync after release.
- Recompute snap pixel values on resize/orientation (listen to `resize`, re-read `getSheetHeights()`); keep current snapIndex.

**Handle + summary:** A grab handle pill at the top (`var(--color-border)` capsule, ~36×4px, centered) inside a header region. Directly under it render `{summary}` (the peek strip). Tapping the handle should also cycle: a plain `onClick` on the handle that advances peek→half→full (and full taps do nothing / stay) — RESEARCH says "tapping the handle also works". Distinguish tap from drag by a small movement threshold (e.g. if total drag < 6px treat pointerup as a tap → advance one detent).

**Scrim:** A sibling element inside the sheet's fixed container (`position: fixed; inset: 0`) at z-index just below the sheet body. Render/fade it in ONLY when `snapIndex === 2`. `pointer-events: none` at peek/half (map stays interactive); `pointer-events: auto` at full so a backdrop tap calls `onSnapChange(1)` (collapse to half). Background `rgba(0,0,0,0.25)` — a fixed value is acceptable per RESEARCH (scrim behavior doesn't change in dark mode); transition opacity 200ms.

**Content area:** A child wrapper with `overflow-y: auto; overscroll-behavior: contain; flex: 1` holding `{children}`. The OUTER sheet wrapper must be `overflow: visible` (RESEARCH Pitfall 6 — the DateRangePicker `drp-popover` is `position:absolute;z-index:100` and would be clipped); clip the rounded top corners with `border-radius` on the visible body, not `overflow:hidden` on the wrapper.

**CSS (`MobileBottomSheet.css`) — token-driven only, no hardcoded colors except the scrim rgba:**
- Sheet body background `var(--glass-bg)`, `backdrop-filter: var(--glass-blur)`, `border-top: var(--glass-border)`, `box-shadow: var(--shadow-glass)`, top corners `border-radius: var(--radius-xl) var(--radius-xl) 0 0`.
- Full-height uses `height: 100dvh` with fallback `height: calc(100vh - env(safe-area-inset-bottom))` (RESEARCH Pitfall 5 — iOS Safari 100vh).
- `z-index: 40` on the sheet (per RESEARCH z-index stack; search bar will be 50, loading 200).
- Handle pill: `var(--color-border)`, `border-radius: var(--radius-full)`, `cursor: grab`, `touch-action: none`.
- Optional landscape guard (RESEARCH Open Question 1): `@media (orientation: landscape) and (max-height: 500px)` caps the half detent at ~70% height — implementer's call; include if low-cost.

i18n: this primitive renders NO literal user-facing strings of its own (summary text is passed in by Plan 03). Do not hardcode any. Any aria-label you add (e.g. on the handle) MUST be a prop or a t() call — but prefer leaving labels to Plan 03 which has the i18n keys; if you add a handle aria-label here, accept it as an optional prop rather than hardcoding.
