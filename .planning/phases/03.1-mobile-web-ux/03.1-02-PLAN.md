<objective>
Build the Airbnb-style compact `MobileSearchBar` from the locked CONTEXT decisions: a slim floating pill that shows the current selection (location + dates + one criterion icon), expands inline at the top into a larger search form (not a page, not the sheet), and is ONE unified bar for both modes — the route/finder choice lives inside the expanded form as a two-segment toggle.

**Ownership boundary (checker BLOCKER — read carefully):** The expanded `MobileSearchBar` form is the COMPACT SELECTION affordance only. It owns the unified mode toggle plus the three store-driven shared inputs (`DateRangePicker`, `LocationInput`, `CriteriaSelector`) and nothing else. It does NOT render `RouteConfigStep`, `WeatherFinderStep`, or call `useOptimizer()`. The actual LAUNCH step (the route-config controls + generate CTA via the hoisted optimizer, or the weather-finder step) lives in `EntryPanel`, which Plan 03 renders as the bottom-sheet content in entry mode. So: **pill = compact selection at the top; sheet (EntryPanel) = the launch step (and later results/detail).** This avoids showing the inputs twice and avoids the optimizer-worker problem: `useOptimizer()` is deliberately hoisted in `EntryPanel` (EntryPanel.tsx:23-24) so the worker ref survives `RouteConfigStep` unmounting; rendering `RouteConfigStep` here would need `onGenerate={optimizer.run}` and would either fail type-check or spawn a second worker. Do not do it.

It reuses the existing `DateRangePicker`, `LocationInput`, `CriteriaSelector` unchanged, and reuses the criterion icons via a new shared `criterionIcons.ts` module (extracted from `CriteriaSelector` so the icons are defined once).

This plan ships the component + the shared icon module + its i18n keys only. It does NOT render the bar in `routes/index.tsx` (Plan 03 composes it and drives its hide-on-full-sheet behavior). It runs in parallel with Plan 01 — no shared files.

Purpose: deliver the top half of the map-first UI (the compact search/selection affordance) as a self-contained, fully-i18n'd, token-themed component.
Output: `MobileSearchBar.tsx`, `MobileSearchBar.css`, the shared `criterionIcons.ts` (+ the one-line CriteriaSelector import swap), and the `mobile.*` i18n keys (EN+DE) that both Plan 02 and Plan 03 will consume.

Out of scope: the bottom sheet (Plan 01); the launch step / optimizer (stays in EntryPanel, composed by Plan 03); index.tsx wiring / hide-on-full / map padding / CSS cleanup (Plan 03).
</objective>

**Component contract:**
```typescript
interface MobileSearchBarProps {
  isExpanded: boolean;
  onExpandedChange: (expanded: boolean) => void;
  hidden?: boolean;   // Plan 03 sets true when sheet is at full → bar animates out
}
```

**Collapsed pill (RESEARCH Pattern 3 + "Compact Search Bar — Reusing Existing Inputs"):**
- A 48px-tall fixed pill, `position: fixed; top: var(--space-3); left: var(--space-3); right: var(--space-3); z-index: 50`.
- Content derived PURELY from store (no new fetch): read `searchAreas`, `tripConfig` via `useAppStore()`.
  - Location = `searchAreas[0]?.name` (PlaceArea has `.name`; for polygon/radius with no name, fall back to `t('mobile.search_placeholder')`).
  - Dates = format `tripConfig.startDate`..`tripConfig.endDate` compactly as e.g. "3.–6. Jun". Use the user's locale via `i18n.language` (de/en) with `Intl.DateTimeFormat` (day + short month); if no dates set, omit the date fragment. If nothing is set at all, show `t('mobile.search_placeholder')`.
  - Criterion icon = first of `tripConfig.criteria`. Import the shared icons: `import { CRITERION_ICONS } from '../entry/criterionIcons';` and render `CRITERION_ICONS[tripConfig.criteria[0]]`. Do NOT rebuild icons (Task 2 created the shared module).
- The pill is a `<button>` with `aria-label={t('mobile.search_bar_open')}`; `onClick` → `onExpandedChange(true)`.

**Expanded form (COMPACT SELECTION ONLY — no launch step):**
- When `isExpanded`, the pill expands to auto-height (drop-down) container, still fixed at top, with a close `<button aria-label={t('mobile.search_bar_close')}>`. Closing → `onExpandedChange(false)`.
- Top of the form: a two-segment mode toggle (`<button>` pair) — `t('mobile.mode_route')` / `t('mobile.mode_finder')`. Selected segment derives from store `mode` (route-config/results → route; weather-finder → finder; idle → use a local default of route). Clicking a segment calls `setMode('route-config')` or `setMode('weather-finder')` from the store. This replaces EntryPanel's two verbose CTAs on mobile — but ONLY the toggle; the step that the chosen mode opens still renders in EntryPanel inside the sheet.
- Below the toggle render the three existing shared inputs UNCHANGED: `<DateRangePicker />`, `<LocationInput />`, `<CriteriaSelector />`. These read/write the store directly — no props to thread.
- **Do NOT render `RouteConfigStep`, `WeatherFinderStep`, or call `useOptimizer()` here.** The launch step is owned by `EntryPanel` (rendered as sheet content by Plan 03). The user picks mode + selection here in the pill; the sheet shows the launch step. Rationale (checker BLOCKER): `RouteConfigStep` needs `onGenerate={optimizer.run}` and the optimizer worker is hoisted in EntryPanel so its ref survives the step unmounting — re-rendering it here would duplicate the form, duplicate inputs, and risk a second worker / type error.
- After the user sets mode + selection, closing the pill (or the sheet's auto-rise in Plan 03) surfaces the launch step in the sheet. The pill's job ends at "compact selection".

**CSS (`MobileSearchBar.css`) — token-driven only:**
- Pill: `background: var(--color-surface)`, `box-shadow: var(--shadow-glass)`, `border: var(--glass-border)`, `border-radius: var(--radius-full)`, `color: var(--color-text)`; muted fragments `var(--color-text-muted)`.

The popover at z-index 100 sits within the bar's z-index 50 stacking context and renders above the sheet (z-index 40).

- `z-index: 50` (above sheet's 40).

i18n: every visible string and aria-label/title MUST use `t('mobile.*')` from Task 1 — no hardcoded strings. Date formatting uses `i18n.language` for locale, not a hardcoded locale string.
