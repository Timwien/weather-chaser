**Collapsed pill (RESEARCH Pattern 3 + "Compact Search Bar — Reusing Existing Inputs"):**
- A 48px-tall fixed pill, `position: fixed; top: var(--space-3); left: var(--space-3); right: var(--space-3); z-index: 50`.
- Content derived PURELY from store (no new fetch): read `searchAreas`, `tripConfig` via `useAppStore()`.
  - Location = `searchAreas[0]?.name` (PlaceArea has `.name`; for polygon/radius with no name, fall back to `t('mobile.search_placeholder')`).
  - Dates = format `tripConfig.startDate`..`tripConfig.endDate` compactly as e.g. "3.–6. Jun". Use the user's locale via `i18n.language` (de/en) with `Intl.DateTimeFormat` (day + short month); if no dates set, omit the date fragment. If nothing is set at all, show `t('mobile.search_placeholder')`.
  - Criterion icon = first of `tripConfig.criteria`. Reuse the existing icon set: export the `ICONS` map (or a `CriterionIcon` helper) from `CriteriaSelector.tsx` if not already exported, and render `ICONS[tripConfig.criteria[0]]`. Do NOT rebuild icons. If you must add an export to `CriteriaSelector.tsx`, add `export` to the existing `ICONS` const only — no behavior change. (Note this in the SUMMARY since it touches an existing file.)
- The pill is a `<button>` with `aria-label={t('mobile.search_bar_open')}`; `onClick` → `onExpandedChange(true)`.

**Expanded form:**
- When `isExpanded`, the pill expands to auto-height (drop-down) container, still fixed at top, with a close `<button aria-label={t('mobile.search_bar_close')}>`. Closing → `onExpandedChange(false)`.
- Top of the form: a two-segment mode toggle (`<button>` pair) — `t('mobile.mode_route')` / `t('mobile.mode_finder')`. Selected segment derives from store `mode` (route-config/results → route; weather-finder → finder; idle → use a local default of route). Clicking a segment calls `setMode('route-config')` or `setMode('weather-finder')` from the store. This replaces EntryPanel's two verbose CTAs on mobile.
- Below the toggle render the existing inputs UNCHANGED: `<DateRangePicker />`, `<LocationInput />`, `<CriteriaSelector />`. These read/write the store directly — no props to thread.
- Below the inputs, render the mode-specific step so the user can actually launch: if route mode, render `<RouteConfigStep .../>`'s relevant controls or its generate CTA; if finder, `<WeatherFinderStep />`. Keep it simple — reuse the existing step components rather than reimplementing. (RESEARCH: "These step components are already extracted and can be rendered below the shared inputs.") If wiring a full step here is heavier than expected, at minimum render the mode toggle + the three shared inputs + the existing launch CTA so search is reachable; document the exact composition in the SUMMARY.

**CSS (`MobileSearchBar.css`) — token-driven only:**
- Pill: `background: var(--color-surface)`, `box-shadow: var(--shadow-glass)`, `border: var(--glass-border)`, `border-radius: var(--radius-full)`, `color: var(--color-text)`; muted fragments `var(--color-text-muted)`.
- Expanded container: `var(--glass-bg)` + `backdrop-filter: var(--glass-blur)` + `border-radius: var(--radius-xl)`, `box-shadow: var(--shadow-glass)`, padding `var(--space-4)`.
- `overflow: visible` on the expanded container so the `DateRangePicker` `drp-popover` (`position:absolute; z-index:100`) is not clipped (RESEARCH Pitfall 6 / Compact Search Bar note). The popover at z-index 100 sits within the bar's z-index 50 stacking context and renders above the sheet (z-index 40).

- `z-index: 50` (above sheet's 40).
