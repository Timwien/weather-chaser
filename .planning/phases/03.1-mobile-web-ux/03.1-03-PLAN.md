**1b. Fix `FitRouteOnSelection` (lines ~49–69).** Before calling `fitBounds`, reset accumulated padding (RESEARCH Pitfall 1 / MapLibre issue #4095): `map.getMap().setPadding({ top: 0, right: 0, bottom: 0, left: 0 });`. Then replace the uniform `padding: 60` with directional padding that reserves the sheet area:
```typescript
const bp = sheetBottomPadding ?? 0;
map.getMap().setPadding({ top: 0, right: 0, bottom: 0, left: 0 });
map.getMap().fitBounds(
  [[Math.min(...lngs), Math.min(...lats)], [Math.max(...lngs), Math.max(...lats)]],
  { padding: { top: 60, right: 60, left: 60, bottom: bp + 60 }, maxZoom: 9, duration: 600 },
);
```
Add `sheetBottomPadding` to the effect deps so a snap change re-fits. Keep desktop behaviour identical: when `sheetBottomPadding` is undefined/0 the result is effectively the old uniform 60 padding.

**1c. Finder fit.** `FlyToFinderRank1` uses `flyTo` (no padding) — per RESEARCH leave the flyTo as-is, but if any finder `fitBounds` exists, apply the same reset+directional-padding pattern. (FinderMarkers fit-on-first-load may live in `FinderMarkers.tsx`; if so, the bottom-padding awareness can be deferred — note in SUMMARY. The route fit is the primary requirement.)

**1d. The work here in `MapContainer` is to ensure the marker `onClick` only drives the popup + the existing fly behavior, and to NOT introduce any new sheet-snap side effect. Confirm StopMarkers/FinderMarkers already setPopupIndex internally (they do) — no change needed there.
