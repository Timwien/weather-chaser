# Phase 3.1: Mobile Web UX - Context

**Gathered:** 2026-06-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the current mobile two-screen tab layout (today: a bottom `MobileTabBar` toggles
between a full-screen panel and a full-screen map, via `mobileView` state in
`apps/web/src/routes/index.tsx`) with a **map-first** mobile layout: the map is always the
background, an Airbnb-style **compact search bar** floats on top, and the trip-config /
itinerary / finder panels appear as a **draggable bottom sheet** over the map. Applies to
both product modes (route planning + weather finder). **Desktop layout is not in scope and
stays as-is.** No new product capabilities — this is a mobile presentation/interaction
rework of existing features only.
</domain>

<decisions>
## Implementation Decisions

### Compact search bar (top)
- Stays **slim/compact**; collapsed it shows the current selection: **location + dates + a single main-criterion icon** (e.g. "München · 3.–6. Juni" + ☀ icon).
- Tapping it **expands inline at the top** into a larger search form (NOT a separate full-screen page or the bottom sheet). Collapses back when done.
- **Floats at the top** over the map; **hides/animates out when the bottom sheet is pulled up** so it doesn't compete with the sheet.
- **One unified search bar for both modes** (route + weather finder); the mode is chosen inside the expanded form, not via separate entry points.

### Bottom sheet (panel)
- **Three snap heights: peek / half / full** (Apple/Google-Maps style).
- Driven by **dragging a handle** (swipe gesture) at the top of the sheet; tapping the handle also works.
- The **minimized peek strip shows a short summary** that invites pulling up — e.g. "6 Orte gefunden" or "Route: 5 Stopps · 480 km".
- **Light scrim/dim over the map only at the full height**; at peek/half the map stays bright and interactive.

### Map-first flow & navigation
- **Remove the bottom `MobileTabBar` entirely** — no more Search/Map toggle. The map is always the background; the search bar + sheet are the whole UI.
- **Automatic flow:** after the user searches, the sheet **rises with results**; tapping a list item (place/stop) opens its **detail in the same sheet** (push/expand within the sheet).
- Tapping a **map marker shows a mini info-popup on the map** (small card at the marker); the sheet itself is not forced to change.
- The map **auto-fits to the results/route**, and the fit **accounts for the area covered by the sheet** (pad the visible region above the sheet so markers aren't hidden behind it).

### Scope / both modes
- The new map-first layout applies **uniformly to both modes** (route planning and weather finder): same search bar, same bottom-sheet pattern, sheet content differs (itinerary vs ranked finder list).

### Claude's Discretion
- **Mobile breakpoint:** user deferred → use **≤ 768px** (matches the existing `@media (max-width: 768px)` rules already in the CSS). Phones + portrait tablets.
- **Landscape handling:** user deferred → keep map-first; let the sheet adapt (lower max height, or a side panel if that proves clearly better) — implementer's call.
- **Desktop untouched:** goal says desktop is unchanged; treat desktop as fixed. Minor polish on desktop only if a shared component refactor unavoidably requires it — avoid by default.
- Animation timings/easing, handle styling, scrim opacity, exact peek-summary wording, marker mini-popup design, and how the inline-expanded search form is laid out.
</decisions>
